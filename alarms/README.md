# alarms

The standard CloudWatch alarms for an environment, all sending to one SNS topic that emails you.

## Alarms

| Area | Alarm |
|---|---|
| ALB | 5xx responses generated by the load balancer |
| Target groups | Unhealthy host count (one per service) |
| ECS services | CPU and memory (one pair per service) |
| RDS | CPU, free storage and connections (per instance) |

Each part is optional: leave `alb_arn_suffix`, `ecs_services` or `rds_instance_ids` empty to skip it.

## Usage

```hcl
module "alarms" {
  source = "git::https://github.com/RSA-InfraStructure/Terraform-Modules.git//alarms?ref=alarms-v1.0.0"

  name   = "rsa-staging"
  emails = ["abdul.rehman@renegadesolutions.asia"]

  alb_arn_suffix            = module.alb.alb_arn_suffix
  target_group_arn_suffixes = { api = module.api.target_group_arn_suffix }
  ecs_services              = { api = { cluster_name = module.cluster.cluster_name, service_name = module.api.service_name } }
  rds_instance_ids          = [module.db.identifier]

  tags = { app = "platform", env = "staging", owner = "devops", managed-by = "terraform" }
}
```

## After the first apply

Each email address gets a **confirmation email from AWS**. Alerts do not arrive until the link in it is clicked.

## Inputs

| Name | Description | Default |
|---|---|---|
| `name` | Name prefix | required |
| `emails` | Subscribers | `[]` |
| `alb_arn_suffix`, `target_group_arn_suffixes` | Load balancer alarms | `null`, `{}` |
| `ecs_services` | Services to watch | `{}` |
| `rds_instance_ids` | Databases to watch | `[]` |
| `*_threshold` | Alarm thresholds | 10 / 85 / 85 / 80 / 5 GiB / 80 |

## Outputs

`topic_arn`.

## Cost

About $0.10 a month per alarm. For one ALB, two services and one database this is about 10 alarms, so around $1 a month, plus $1 for the topic's KMS key.
